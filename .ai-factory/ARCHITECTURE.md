# Архитектура: Слоистая (Layered Architecture)

## Обзор
Проект — статический фронтенд без бэкенда: интерактивная карта недр с пошаговой
навигацией. Архитектура — классическое слоистое разделение, адаптированное под
браузерное SPA без фреймворка: слой представления (рендер DOM), слой состояния
(автомат навигации), слой данных (предсгенерированные JSON) и инфраструктура
(обёртка Яндекс.Карт, сгенерированные ассеты).

Выбор обусловлен: соло-разработка, простой домен (области → районы → участки),
низкие требования к масштабированию, отсутствие сервера. Слоистая модель даёт
минимально достаточное разделение ответственности без церемоний DDD.

## Обоснование
- **Тип проекта:** статический лендинг с интерактивной картой
- **Стек:** TypeScript (vanilla, без фреймворка), Vite, Яндекс.Карты API 2.1
- **Ключевой фактор:** простота домена + уже сложившаяся структура `src/js/`,
  которая естественно ложится на слои; нулевая операционная сложность

## Структура папок (как есть, задокументированная реальность)
```
src/
├── index.html                  # Единственная страница, подключает Яндекс.Карты
├── js/
│   ├── main.ts                 # Композиция/вход: инициализация, рендер, обработчики событий
│   ├── navigation.ts           # СЛОЙ СОСТОЯНИЯ: автомат NavState + стек истории
│   ├── dom.ts                  # ПРЕДСТАВЛЕНИЕ: ссылки на DOM-элементы
│   ├── types.ts                # Общие типы (NavState, Plot и др.) — общий контракт
│   ├── data/                   # СЛОЙ ДАННЫХ: участки, регионы (предсгенерированные)
│   ├── map/                    # ИНФРАСТРУКТУРА: обёртка Яндекс.Карт (единственная точка доступа к API)
│   ├── ui/                     # ПРЕДСТАВЛЕНИЕ: рендер списков и карточек
│   └── vendor/                 # ИНФРАСТРУКТУРА: сторонний код, изолирован
├── css/                        # Стили (изменение представления не затрагивает логику)
└── assets/                     # Исходные ассеты
public/                         # Статика: geo (JSON/GeoJSON), шрифты, изображения
scripts/                        # Генерация данных и ассетов (вне runtime-слоёв)
```

## Правила зависимостей
Направление зависимостей — строго вниз (от представления к данным):

- ✅ `main.ts` → `navigation.ts`, `ui/`, `map/`, `data/`, `dom.ts` (композиция всех слоёв)
- ✅ `ui/` → `dom.ts`, `types.ts`, `data/` (рендер читает данные)
- ✅ `navigation.ts` → `types.ts` (чистое состояние, без DOM и API)
- ✅ `map/` → `types.ts`, `data/` (карта отображает данные)
- ❌ `data/` не импортирует `ui/`, `map/`, `navigation.ts` (данные не знают о потребителях)
- ❌ `navigation.ts` не импортирует `ui/`, `dom.ts`, `map/` (состояние без побочных эффектов)
- ❌ `ui/` не вызывает Яндекс.Карты напрямую — только через обёртку `map/`
- ❌ `vendor/` не импортирует код проекта (односторонняя изоляция)

## Коммуникация слоёв
- **События → состояние:** пользовательские клики попадают в `main.ts`, который
  вызывает методы `navigation.ts` (`openDistricts`, `openPlots`, `openObject`, `goBack`)
- **Состояние → представление:** изменение `NavState` вызывает единый `render()` в
  `main.ts`, который делегирует отрисовку функциям `ui/`
- **Данные → представление/карта:** `ui/` и `map/` читают предсгенерированные данные
  из `data/` и `public/geo/`; обратной связи нет
- **Карта:** взаимодействие с Яндекс.Картами инкапсулировано в `map/`; остальной код
  вызывает только её публичный API

## Ключевые принципы
1. **Единый источник состояния навигации:** `navigation.ts` — единственный владелец
   `NavState` и стека истории; `main.ts` только читает через геттеры
2. **Переходы через transition():** все forward-переходы идут через единый
   приватный `transition(next)` — история консистентна, идентичные переходы не пишутся
3. **Данные неизменяемы в рантайме:** участки/регионы генерируются скриптами
   (`scripts/`), в рантайме только читаются; ручное редактирование запрещено
4. **Инфраструктура за обёрткой:** любая работа с Яндекс.Картами — только через `map/`
5. **docs/ — только вывод сборки:** ручное редактирование собранного кода запрещено

## Примечание об организации кода
- **Новые функции:** следуйте слоистым правилам этого документа, где это практически
- **Существующий код:** структура задокументирована как есть; при правках
  придерживайтесь конвенций, но не переписывайте несвязанный код ради структуры
- **Совместимость:** при необходимости вызова существующего кода из нового
  предпочтительны чистые интерфейсы, но рефакторинг только ради выравнивания не нужен

## Примеры кода

### Корректное направление зависимостей (состояние без DOM)
```typescript
// navigation.ts — слой состояния: чистый, без импортов ui/dom/map
import type {NavState} from './types';

// Фабрика, а не класс — стиль проекта
export function createNavigation(callbacks: NavigationCallbacks): Navigation {
  let current: NavState = {
    level: 'regions', region: null, district: null, plotName: null,
  };
  const history: NavState[] = [];                // полная история переходов

  /** Forward-переход: текущий экран уходит в историю (дубли подряд не пишем). */
  function transition(next: NavState): void {
    if (sameState(current, next)) return;        // защита от «мёртвых» кликов
    history.push({...current});
    apply(next);
  }

  function goBack(): void {
    const previous = history.pop();
    if (previous) apply(previous);               // корень — бездействие
  }
  // ...openDistricts / openPlots / openObject через transition()
}
```

### Представление читает состояние и данные (не наоборот)
```typescript
// main.ts — композиция: событие → состояние → рендер
function selectPlot(plot: PlotArea): void {
  selectedPlot = plot;
  plotPolygons?.highlight(plot);
  renderObject(refs, plot);
  navigation.openObject(plot.name);              // 1. состояние
  focusPlot(plot);                               // 2. карта — через обёртку
}
```

## Антипаттерны
- ❌ Прямой вызов `ymaps.*` из `ui/` или `main.ts` — только через обёртку `map/`
- ❌ Хранение состояния навигации в DOM (data-атрибуты как источник истины)
- ❌ Импорт `data/`-модулей из `map/` с мутированием — данные только для чтения
- ❌ Редактирование файлов в `docs/` и сгенерированных данных руками
- ❌ Обход `navigation.ts`: прямое изменение экранов из `ui/`-функций
- ❌ Новый код в `vendor/` — сторонний код туда не добавлять без необходимости
